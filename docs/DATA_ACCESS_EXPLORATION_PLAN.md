# 课程录播取数路径探索计划

更新：2026-11-12。依据用户最新指示：将探索方向写入开发文档、列出探索计划，本轮先不具体开发；保留当前课表导出逻辑，主要优化获取课程录播的路径。

## 当前授权与目标

2026-11-12后续授权：用户要求先备份原开发成果，再按本文开始探索开发，并允许参考GitHub项目。首轮已完成源码备份、独立受限目录适配器、合成检查及桌面官方会话验证，见[实验记录](research/RECORDING_API_EXPERIMENT.md)。下段“本轮只整理”是上一轮授权边界，不再阻止已授权的探索开发；应用默认路径尚未替换，课表导出仍保留。

2026-11-12指南补充：用户提供Android端侧鉴权/媒体指南并授权自行决定采用。[评估记录](research/ANDROID_GUIDE_REVIEW.md)将UA与按目标认证、原生逐资源数据源、错误分类和资源释放纳入E3/E4；不采用认证存储导出、全局凭据转发或默认隐藏嗅探，不为指南建议更换现有技术栈。

本轮只整理计划、检查文档并同步 Git。不修改应用或测试代码，不新增接入原型，不构建/安装，不操作手机、模拟器或学校会话。下列“待探索”是后续任务清单，不因写入计划而在本轮执行；进入应用实施前仍需用户明确继续及确认对应范围。

目标是减少取得本人课程录播所需的页面跳转、组件等待与轮询，同时保持课程来源正确、目录完整、权限校验和失败时旧数据可用。优先探索课程与目录直接请求，再独立研究播放前准备能否简化。课表、播放器交互和其他校园模块不因本计划改变。

建议目标流程：

```text
本人在应用内学校官方页面认证
  → 必要的官方门户/课程平台初始化
  → 官方客户端请求当前学期课程
  → 同名多来源匹配，按来源请求全部录播分页
  → 完整校验后沿用现有原子保存、离线目录
  → 用户选择某条录播
  → 当次权限、水印及实际媒体路由核对
  → 交给现有原生播放器
```

该流程是探索目标；当前默认应用路径尚未替换。目录请求已有桌面证据，播放前准备的新路径仍只有静态接口线索。

## 范围与复用

| 项目 | 本计划处理方式 |
|---|---|
| 课表导出 | 明确保留现有官方页面导航、全部周次选择、XLS下载/解析与DOM备用；不探索或改写其导出路径 |
| 官方登录 | 复用已有可见WebView，探索减少重复进入门户与认证后恢复原录播任务；当前不需要从零开发登录能力 |
| 课程/录播目录 | 核实直接请求、分页、同名来源、异常与兼容性，为后续独立适配器给出依据 |
| 播放前准备 | 单独研究录播详情、当次权限、水印和媒体地址交接，不能用目录成功推断此链路通过 |
| 播放器与本机数据 | 复用既有原生播放器、布局、续播、目录模型、同名收集器和原子保存规则；不同时重写 |
| 排除项 | 自建密码表单、密码/令牌保存、自动重登、后台保活、观看记录上报、实际直播、视频下载及其他模块均不由本计划授权 |

“必要时引入应用内登录”的现行解释是应用内可见的学校官方认证。若后续证据表明必须改变认证策略，先列替代方案和影响，再一次询问一个实质问题，不自行读取认证存储补请求。

### E1：认证与初始化

1. 先核对现有会话及访问方式，不为造测试条件退出或清空本人手机会话。全新认证使用独立环境，由本人操作；不复制已有凭据。
2. 区分官方认证完成、门户可达、课程平台初始化完成、真实课程请求成功四种状态。认证页/空白页/HTTP 200不能单独证明请求已就绪。
3. 观察从课表或本地录播目录进入时，哪些官方步骤确实必要；仅在证据支持时提出缩短导航，不猜造SSO地址或携带认证参数的深链。
4. 研究登录取消、失效、重新认证与返回原课程/原录播身份的处理；网络不可达时保留会话和旧目录，不反复让本人登录。

完成条件：给出最少必需的官方初始化步骤、可观察完成信号和恢复状态图。若必须增加认证存储或自建登录，记录未通过并提交方案确认，不能视为默认实施路线。

### E2：课程与目录完整性

1. 核实学期、官方筛选值和课程参数映射；不切换角色扩大权限，不将本地Course ID当作学校接口参数。
2. 对同学期仅整理空白后的精确同名条目汇总全部来源，教师/班级仍只作来源标签。保留学校课程ID＋录播ID的复合身份，不能跨来源仅按录播ID去重。
3. 在可用且授权的样本中覆盖两页以上、空目录、同名多来源、无匹配、页内重复、缺页及分页总数变化。现场无相应样本时标记未测，列入未来合成验收设计，不修改真实数据制造情况。
4. 对照目录字段、顺序、发布状态和原来源；页间总数或集合变化时不把部分结果认作完整新目录。未来适配应复用现有整组原子保存，失败保留旧目录。
5. 只读取本人有权获取的数据；限制请求次数、超时与串行节奏。性能比较记录环境、是否已有会话及是否已有缓存，不将一次3.2秒结果写为产品性能承诺。

完成条件：形成业务字段白名单、请求参数表、完整性规则和异常分类。成功、空数据、认证失效、无权、服务异常和结构变化必须可区分；无法区分的项目保留为阻碍默认替换的缺口。

### E3：直连、WebVPN与变化兼容

1. 按主机、路径、HTTPS和实际访问方式核实边界；WebVPN只采用官方已验证映射与请求包装，不猜造隧道或回退不受限直连。
2. 官方客户端继续在网页内部处理认证和可选加密。只分析公开实现/配置结构，不读取认证头值，不导出Cookie/令牌或认证存储。
3. 探索当前webpack客户端能否可靠检测、模块缺失/学校构建变化时怎样停止。写明模块号依赖的维护成本，不把当前固定编号作为长期契约。
4. 回退建议按错误原因区分：客户端能力不支持可考虑有限回到既有页面；认证失效先本人官方认证，权限拒绝不绕过重试，服务不可达保留旧数据。不能在新旧路径间循环。
5. Android先评估现有应用、WebView和官方页面可提供的观察能力；不启用WebView调试、不读取其存储。若新API路径必须依赖新增调试/接入代码才能验证，标为“需单独实施实验”，列出范围待确认，未经单独确认不开发或安装。

完成条件：直连/WebVPN、桌面/Android分别有证据或明确缺口；给出可检测的不兼容状态、取消/超时/迟到结果的未来处理建议。没有移动证据时只能建议进入受限试验，不能宣布可默认上线。

### E4：播放前准备的独立研究

1. 以课程来源和录播复合身份核实详情参数，区分已发布、未发布、无权和不存在；点击播放仍需当次权限，不因目录已离线保存而跳过。
2. 确认水印配置、可见画面限制、媒体节点/路径、短期地址及WebVPN最终媒体路由由哪些官方步骤产生。不记录永久媒体地址，不把配置或静态字段当作实际播放成功。
3. 仅观察官方正常产生的请求和本人授权样本；不伪造播放、发布状态、角色或观看时长，不调用观看记录写接口。真实播放/听音若需进行，单独安排本人参与并分别记证据。
4. 比较“目录API＋现有播放准备”和“目录API＋经验证的简化准备”的依赖、成本和权限/水印等价性。现有原生播放器、音画同步、布局、手势和本机续播不在此阶段重写。

完成条件：写清能减少哪些页面步骤、哪些必须保留、直连和WebVPN各自未验证项。媒体请求成功、播放器开始、实际听音及完整课时验收分开；如不能证明权限与水印等价，就保留现有播放准备。

### E5：转入开发前的可审查方案

优先候选为“仅替换录播课程与分页目录取数，保留官方认证和现有播放准备”；E4证据充分后再提出独立播放准备分项。实施建议至少包括：

- 准备复用的模型、同名多来源收集器、原子保存和会话生命周期，以及拟新增/修改的文件与接口边界。
- 有限动作白名单、业务字段映射、兼容检测、取消/超时/认证恢复与有限回退行为；接口不得接受任意URL、脚本、请求头或角色。
- 合成验收设计：缺失客户端、错误封套、空页/重复/总数变化、同名多来源、取消/退出后的迟到结果及旧目录保护。
- Android本人授权验收清单：直连/WebVPN、首次/已有/失效会话、单课/统一导入、来源恢复及与旧路径对照；真实数据不进入CI。
- 每个分项独立检查、记录证据、提交与普通推送；构建、安装、版本和发布按实际实施授权处理，不由研究文档自动启动。
