# 统一录播导入停滞修复计划

日期：2026-11-11。用户授权依据录屏制定计划并测试、修改。录屏及关键帧仅在被忽略的本机目录分析，不提交。

## 已定位的问题

录屏显示已登录WebVPN门户，约23秒后耗尽读取轮次；随后“重试当前课程”在门户页调用课程平台内部路由，错误提示数据变化。现有入口只查找特定门户卡片，未区分入口未呈现、未支持路径和课程数据超时。后续还出现一次跳转被拦截，但录屏不足以确认具体目标，不放宽TLS或域名校验。

## 修改与验收顺序

1. 拆分等待认证、WebVPN门户、平台入口、课程数据四个阶段；认证等待不消耗自动读取次数，仅App前台检查当前页面，不新增后台保活、重登或密码保存。
2. 保留现有门户卡片导航；只有学校HTTPS WebVPN明确呈现已登录门户标志时，使用已验证的qhz HTTPS隧道cc入口，避免依赖卡片名称/布局。未知路径、未知隧道、HTTP及其他目标仍拒绝，不根据任意页面文本生成地址。
3. 继续导入先读取当前页状态：门户/认证恢复入口识别，已进入课程平台才调用内部目录路由；重试保留已经完整导入的课程。分别提示入口等待、弹窗、路径不支持、跳转受限及数据超时。
4. 合成测试覆盖嵌入式登录、门户分组但没有教学卡片、等待认证超过旧上限、分阶段超时、恢复与后台暂停；保留名称匹配、完整分页和本地目录回归。
5. 静态分析、Flutter回归及Java/DOM合成检查后构建普通调试包，保留数据安装。真实学校验证由本人扫码，区分页面展示、门户导航和完整导入的验证状态；不清除现有会话或将合成通过写成其他设备已修复。

## 交付边界

本次为同一项导入恢复修复，检查完成后提交并推送当前分支。版本不变，不替换v0.25旧发布附件，不实施账号加密保存/自动重登专项。实际结果在STATUS及DEVELOPMENT_PLAN补录。

## 本轮执行结果

- 步骤1–3已实现；补充真实模拟器发现的非首页原生WebVPN扫码页识别、课程平台尚未初始化的loading状态，以及自动选择VPN后不再重复直连回退。
- 步骤4通过：76项Flutter检查（另1项可选预览跳过）、静态分析及Java/XLS/DOM/媒体传输离线检查通过，包含连续恢复及后台暂停场景。
- 步骤5部分通过：最终普通调试包已验证ZIP/脚本资产并保留数据安装；真实扫码页已正确等待本人认证，完整导入仍待本人扫码。其他设备录屏中的原始门户DOM未取得，固定入口方案的该设备实效仍需复测，不作全面通过声明。
