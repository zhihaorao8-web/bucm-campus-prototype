## 每项修改的执行顺序

1. 查看Git工作区、需求决策、已有实现及当前证据，说明本项要解决的具体问题。
2. 实现单一目的的修改；保留其他人的未提交工作。涉及新范围或认证策略时先按一次一个问题澄清。
3. 运行与修改匹配的检查。DOM/解析变更跑对应合成测试；UI变更检查布局、交互和必要预览；真实学校验证仅限授权手动会话，不进入CI。
4. 更新本清单相应阶段和`STATUS.md`中的证据；有范围/UI规范变化时同时更新`PROJECT_BRIEF.md`/`DESIGN.md`。只写实际完成的结果，失败也保留记录。
5. 仅暂存本项相关文件，提交并普通推送当前工作分支。成功后记录提交；失败时说明本地提交与远程状态，再处理阻塞，不强制推送。
