# 学校登录状态长期复用测试

启动日期：2026-11-11。用户确认首轮目标为**一次本人登录后至少7天免重复登录**，服务于课表按需刷新与后续直播访问。本轮是可行性测试，不新增保存密码、自动扫码、后台定时保活或自制续期功能。

## 判断标准

目标首先按日常前台使用、期间可关闭应用或重启设备解释。连续使用7天与完全闲置7天是两个不同结果；前台访问可能触发学校自己的滑动续期，不能混为一谈。

必须使用同一Android应用自己的WebView环境。Ego Lite、其他浏览器和模拟器浏览器的会话不能代替App证据。强制结束应用或冷启动设备后，重新从官方服务取得数据；命中5分钟内存列表、打开离线课表、看到登录页返回200，都不算认证复用成功。

扫码和账号密码均由本人在学校官方页面操作。测试记录只保留时间、登录方式（本人确认）、业务阶段、是否要求重新认证和固定错误类别；不读取或导出Cookie数据库、密码、验证码、令牌、原始请求/响应或真实课程。

## 现有实现核对

- 应用使用普通系统WebView和统一的默认会话环境，没有开启无痕或为课表/课堂建立独立凭据文件。
- 锁定的`flutter_inappwebview_android 1.1.3`在页面完成时调用`CookieManager.flush()`。Android官方[CookieManager说明](https://developer.android.com/reference/android/webkit/CookieManager#flush())确认该方法将当前可访问Cookie写入持久存储；这不能延长服务端有效期，也不是承诺所有服务器会话在重启后有效。
- 清除学校登录才删除Cookie和Web存储。打开课表导入只清除短时课堂页面缓存，不清除学校登录环境。
- WebVPN、统一认证、教务与课堂业务各自可能失效；统一认证尚有效时，官方正常重定向可能重新建立业务会话。业务无需手动登录不等于原业务令牌仍未过期。
- 未发现可以据此确认学校至少7天有效的公开配置证据；未提取任何账号的凭据过期字段，也未修改过期时间或设备时钟。
