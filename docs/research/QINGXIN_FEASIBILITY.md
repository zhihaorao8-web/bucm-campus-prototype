# 轻新课堂直播与回放接入可行性

调研日期：2026-11-10。基线：Flutter Android 0.2，源码工作分支`codex/auto-course-import`。本轮仅获准调研，不表示已批准新增模块开发或发布。

## 结论

**回放具备较明确的接入可行性；直播具备页面和权限配置线索，实际播放仍待验证。** 在用户本人完成官方认证的Ego Lite会话中，已从数字北中医应用中心进入现行平台、读取本人课程及录播列表，并短时播放一个录播样本，三路视频均产生解码帧，随后暂停。没有在Flutter应用、Android WebView或原生播放器中复现，不将桌面浏览器成功记作Android验收通过。

建议第一步做Android内的官方页面与播放器接入验证，保留学校自身的权限判断、水印和观看记录；原生课程列表、课表关联及独立播放器按验证结果逐项推进。现有项目可继续采用无开发者后端、本人官方登录的架构，不需要恢复密码保存或静默重登。

## 当前有效入口与旧站纠正

用户明确指出搜索到的旧轻新课堂页面已停用，并指定从数字北中医应用中心进入。本轮实际路径为：

1. [数字北中医](https://i.bucm.edu.cn/) → 学校统一身份认证；认证页位于`https://cas.bucm.edu.cn`，扫码由用户操作。
2. 应用中心 → **“岐黄智”AI教学平台（轻新课堂）**。
3. [现行平台](https://qhz.bucm.edu.cn/cc/) → 课程教学 → 课程平台。
4. `https://qhz.bucm.edu.cn/coursePlatform/` → 本人课程 → 课程视频 → 录播视频 → 查看。

学校[教务处常用服务](https://jxw.bucm.edu.cn/cyfw/)本次仍指向`qxkt.bucm.edu.cn:88`的旧HTTP入口；搜索还返回8081旧站。对旧站443、88、8081的HTTPS尝试失败，仅代表本次旧入口探测结果。**这些结果不用于推断现行平台不支持HTTPS或需要放开明文流量。** 学校2020年的旧说明只能作为历史资料，不能代替当前部署的验证。

## 证据与验证边界

| 项目 | 本轮观察 | 能支持的结论与限制 |
|---|---|---|
| 官方认证与跳转 | 用户登录数字北中医后，应用中心可打开岐黄智与课程平台 | 桌面官方会话链路通过；未证明Flutter WebView兼容、长期续期或第三方正式SSO授权 |
| 本人课程 | 可读课程列表、学期、课程编号、课程序号 | 存在可用于结构化的元数据；未开发解析器，也未验证全部课程或跨学期完整性 |
| 录播列表 | 可见授课时间、教室、发布状态与查看入口 | 页面列表可读；不是完整学期准确导出结论 |
| 回放实际播放 | 一个样本的老师、学生、课件三路视频均进入播放，时间推进至约2秒并产生解码帧；操作后暂停 | 当前桌面会话的一次短时播放通过；未验收长时稳定性、音频听感、拖动、倍速、全屏、断网恢复或所有教室 |

| 媒体地址 | 样本使用`https://qxkt4.bucm.edu.cn:8880` | 网页API域名与媒体域名/端口不同；未知其他教室是否使用其他节点 |

| 多画面 | 官方播放器具有老师、学生、课件切换及布局控件；还列有黑板/平板选项 | 三路视频已解码；黑板、平板、布局切换和精确同步未实测 |

| 直播实际播放 | 未取得可由当前官方界面进入的进行中课堂 | 未验证直播列表、协议、延迟、媒体节点、实际权限及Android播放 |
| Flutter/Android | 只核对现有代码与依赖 | 本轮未改应用、未装播放器、未构建、未在模拟器或真机验证该模块 |

本轮未导出Cookie、令牌、WebView存储或HAR，未保存真实视频、课程JSON或截图到仓库。浏览器工具临时显示的页面内容不作为测试夹具或提交材料。

## 可复核的接口线索

以下来自已授权官方页面实际加载的资源路径或前端方法。只记录通用路径和字段名，不保存参数值、课程标识、媒体完整路径、请求头或认证数据。它们是网站内部实现线索，**不是公开稳定API或学校授予的第三方接入协议**；请求方式、分页、错误格式、会话失效和兼容范围仍需单独核实。

| 路径/前端结构 | 用途线索 |
|---|---|
| `/cp/course/getCourseList` | 本人课程列表 |
| `/cp/courseSchedule/list` | 排课与日期关联 |
| `/cp/courseInfo/getStudentLivePermission` | 学生直播相关配置 |
| `/cp/courseInfo/ResourceList` | 列表与回放详情加载；详情前端读取`res.courseSched`和`res.streamMap` |
| `/cp/courseInfo/getCourseSchedDetail` | 排课详情 |
| `#/listenCourseLive` | 周课表的直播页面路由；由课程、教室、课次参数组成，当前未打开实际直播 |
| `streamMap` | 存在`teaStreamHlsUrl`、`stuStreamHlsUrl`、`vgaStreamHlsUrl`等字段 |
| `/bd/teachingVisitConfig/getWaterMarkStatus` | 播放器加载前获取水印配置 |
| `/bd/tqaListenRecord/add` | 官方播放器配置的观看时长记录地址；本轮未独立调用、未核验服务端计时结果 |

不能只复制三条流地址就宣称等价接入。官方前端按可见范围选择流，加载水印配置，并配置观看记录。独立播放器必须核实并尊重这些行为，不得绕过未发布、权限或学校限制；播放时长不得模拟或伪造。

## 与现有工程的衔接

- `mobile/lib/ui/import_page.dart`已有可见官方WebView、窗口跳转、TLS失败终止和会话退出处理。可复用基础能力，但课程模块应有独立导航与状态；不能让课表自动导出脚本在课程页面运行。
- `mobile/lib/platform/school_adapter.dart`的显式URL校验限定学校HTTPS及443端口。样本媒体8880不能直接传给这套导出校验。应为媒体单独设计精确主机/端口及重定向检查，不全局放开端口或TLS。现有导航回调也不等于已全面校验WebView子资源，需在Android上单独核实。
- 当前官方页面和媒体均观察到HTTPS，不需要启用`usesCleartextTraffic`或混合内容，也不需要开发者服务器中转学校凭据。
- 现有`Course.id`未定义为岐黄智的`courseId`，模型也没有专用外部课程序号字段。后续应建立带平台与学期的独立关联，不能把现有本地ID当作平台ID，更不能仅按课程名自动绑定。匹配歧义应留给用户选择，不覆盖原课表。
- 官方页面的课程上下文由前端状态及窗口导航传递。复制页面hash不保证可独立打开，应测试完整导航、冷启动、会话过期和多窗口返回。
- 当前未依赖独立播放器。本轮不选定或安装`media_kit`等库；选型应以Android单流解码、会话使用、跨域媒体、重定向与多流同步的最小验证为依据。
- Ego Lite的登录状态不转移到应用。后续Android验证仍需用户在应用自己的官方页面登录。

## 接入方案比较

| 方案 | 可提供的体验 | 主要待验证事项 | 建议 |
|---|---|---|---|
| 官方WebView | 应用内进入官方课程、录播及直播页面，复用学校播放器 | Android布局、多窗口、三路解码性能、全屏/旋转、媒体端口、登录过期、观看记录 | 优先做最小接入验证；技术风险相对较低，仍未达到Android通过状态 |
| 原生列表＋官方播放器 | 自有课程/录播列表、课表详情关联，播放时进入官方页面 | 元数据适配、外部ID映射、官方页面上下文、失效与未发布状态 | 列表和关联验证后可作为正式首阶段范围 |
| 原生列表＋独立播放器 | 自定义播放控件、切换/多画面、倍速与本机进度 | 播放请求认证、URL寿命、节点变化、流同步、水印与真实观看记录、直播协议、长时稳定性 | 有技术可能，工作量及维护风险最高；不以桌面样本替代原生验证 |

## 建议的下一阶段范围与验收

以下是待用户确认的开发建议，本轮未实施：

1. **先验证官方播放器在Android运行。** 独立页面完成本人登录与课程导航，打开已发布回放；核验暂停、前后台、全屏、旋转、返回及退出会话。长时播放与三路画面实际性能分别记录。
2. **补真实直播证据。** 在本人有权限且官方页面显示进行中的课程时，由正常入口进入；记录实际协议、主机/端口、权限拒绝和开播/结束状态。未到授课时间不伪造进行中状态。
3. **实现原生列表与关联。** 定义平台课程、课次、回放及播放能力模型；只在本机保存必要元数据与关联，不落地凭据或永久保存带授权参数的流地址。合成测试覆盖分页、同名课程、过期、空列表、未发布和权限拒绝。
4. **按需验证独立播放器。** 先单流，再画面切换，再评估多流同步；实测真实观看记录和水印等价性后才决定是否替换官方播放器。

建议首阶段功能限于本人课程、已发布回放和官方允许的直播入口，不加入下载、后台播放、签到、作业、AI教学或其他校园模块。具体页面形态及交付验收需下一次范围确认。
