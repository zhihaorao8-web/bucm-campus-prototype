# 录播自动获取与会话刷新评估

日期：2026-11-11。用户要求先实现按名称自动获取，再评估保留登录状态用于自动刷新；本轮不增加后台定时任务或密码保存。

## 自动获取的边界

进入本人课程后自动检测路径、沿学校资源入口进入平台，再按同学期的名称匹配课程并读取录播。名称整理首尾和连续空白，不使用教师、包含关系或近似文本猜测。唯一候选可自动关联；多个同名候选须有仍有效的已有ID关联，否则由本人选择。未知学期、错误旧映射和重复ID不能静默关联。

只操作已观察到的“智慧教学平台”和“课程平台”两个官方按钮。按钮原本打开的新窗口在同步动作期间改为受限的同页导航，目标仅允许对应HTTPS主机/端口和精确WebVPN映射；入口脚本只返回状态，不通过数据提取结果传输URL参数，不放开通用程序弹窗。正常官方导航由WebView处理，导航回调不持久化或记录地址。登录、扫码、授权提示和其他对话框由本人操作。手动返回或切换访问方式可打断自动导航，失败有重试入口；不循环重登。

本轮仍读取官方当前页面的分页数据，不宣称已准确导出完整学期全部录播。自动获取不等于自动播放。

## 会话保留机制

现有普通WebView使用Android系统会话存储，插件未启用无痕模式。已核对锁定的`flutter_inappwebview_android 1.1.3`：`InAppWebViewClient`及Compat实现在页面加载完成时调用`CookieManager.flush()`，不需要再建独立Cookie文件。

Android的[CookieManager文档](https://developer.android.com/reference/android/webkit/CookieManager#flush())说明，flush负责将当前Cookie写入持久存储，过期条目仍由WebView清理。**本机保存不能延长学校服务器授予的有效期。** 本项目不会复制浏览器凭据到Dart、日志或开发者服务，也不修改服务器过期字段。

此前Android授权会话已经在多次应用进程重启、保留数据覆盖安装后继续访问目录和媒体；这证明当时的会话可以复用，未证明跨天、设备重启、账号切换或学校策略变化后仍长期有效。学校WebVPN、统一认证及课程平台可能有不同有效期，目前未测定；本轮未读取或导出Cookie值、令牌、密码或验证码。

## 可行性判断

| 场景 | 判断 | 必要条件/限制 |
|---|---|---|
| 再次打开课程自动获取录播 | 采用本轮自动获取流程 | 网络可达、当前官方会话有效、名称匹配无歧义 |
| 重启应用后继续获取 | 本轮自动流程重启复测通过 | force-stop后只点击课程仍自动取得列表，未重新登录；有效期未测定 |
| 页面保持前台时自动刷新列表 | 技术上可继续实现 | 需要实际重发官方列表请求、限制频率、避免覆盖翻页/播放/手动选择；仅重读旧DOM不算刷新服务器数据 |
| 学校登录过期后继续刷新 | 暂不能保证 | 显示官方认证页，由本人完成后继续；没有已验证的官方续期协议，不模拟刷新令牌或自动扫码 |
| 后台定时刷新/跨天无人值守 | 本轮未实现，证据不足 | 需另行设计后台执行、缓存隔离、网络及认证失效处理；不能用前台成功替代 |

建议后续优先做“进入课程/返回前台时，在有效官方会话下按需刷新”，再评估是否值得加入后台调度。默认不通过定时访问登录页来保活，也不伪造观看时长或调用未验证的续期接口。

## 验证状态

名称匹配、启动/取消和入口约束已具备合成检查；授权Ego Lite已验证资源入口到平台目录的两步自动导航。Android已验证只点击课表课程后自动出现原生录播列表，未点击连接按钮、官方入口或平台候选；本地ID关联数量从1变为2，确认新课程也由名称规则自动匹配，非仅复用旧关联。随后force-stop重启再点课程，同样自动取得列表且无需重新登录。最终检查的实际结果统一记在[STATUS](../STATUS.md)。会话自然到期、重新认证后自动继续、切换账号和跨天刷新仍需独立验收；不会为了测试主动退出当前学校账号或清理本人数据。

## 短时页面缓存（2026-11-11）

为减少反复进入同一课程的导航，使用现有插件的[Keep Alive机制](https://www.inappwebview.dev/docs/webview/keep-alive/)，原创缓存代码，不复制第三方实现。缓存只保存结构化录播列表、固定入口、获取时间、滚动位置和原生页面的本地句柄；没有提取或新建Cookie/令牌文件，也没有缓存媒体URL和视频。原课堂文档自身的登录环境仍由系统WebView持有。

- 有效期5分钟，从实际获取时起算；缓存命中、本地DOM核对和从播放器返回不会续时。
- 最多保留最近两门离页课程。取用即从空闲池移出，同一句柄不能挂载两个WebView；淘汰/到期/重置后释放，离页时等待原控件解绑再交还缓存。
- key使用本地课程ID、学期、规范化名称；授课日期只影响当次高亮，不切分同一门课的缓存。恢复时核对文档的学校课程ID和学期，文档丢失自动走原连接流程。
- 官方认证、权限、解析及播放失败不保留可复用状态。清除学校登录或打开重新导入课表时清空空闲池并变更代次，防止此前在途页面重新写回旧账号状态。
- 手动刷新和翻页执行原官方分页方法后更新列表；改变关联重新选课。缓存中的列表不证明服务器会话仍有效，播放依然通过学校接口读取当次媒体配置并校验学校来源。
- 到期计时器只清理本地资源，不新增后台网络刷新、密码保存、静默登录或续期能力。

原生播放桥兼容普通平台视图整数ID及KeepAlive的本地字符串句柄，恢复页面也执行相同官方来源检查。此处使用锁定`flutter_inappwebview_android 1.1.3`的插件管理器定位原生WebView；升级插件时必须重验句柄查询、唯一挂载、销毁和实际播放。未修改插件本体、TLS或媒体域名白名单。

## 至少7天目标的后续验证

用户已于2026-11-11确认启动至少7天的长期复用可行性测试。新增实测：保留数据设备冷启动后课堂仍可免登录取得录播；但同一WebVPN会话进入教务时出现统一身份认证页，暂停导入等待本人操作。当前不能把课堂成功外推为教务刷新免登录，也不能把分钟级重启通过写作7天通过。登录方式、各业务T0、跨天复测与直播开放后的验收统一记在[长期会话测试](SESSION_LONGEVITY_TEST.md)。本轮仍未引入后台保活、保存密码或自动续期。

后续A/B短期复测已完成：本人分别不勾选/勾选官方“记住账号密码”登录，两组都能在App强退和设备真实重启后免登录重新获取并保存课表。B组重启后课堂录播列表也可重新取得。B组确认基线为2026-11-11 12:41:13（UTC+8）；7天检查最早为11月18日同一时刻，目前未经过。两组之间有显示修复，不将结果严格归因为该选项的效果；自然过期后的字段回填和自动提交行为未验证。完整结果与后续节点见[长期会话测试](SESSION_LONGEVITY_TEST.md)。
